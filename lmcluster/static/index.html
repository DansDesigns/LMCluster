How models get loaded

        
These apply the next time you load a model. They do
          not affect one that is already running.

        

          
          
          
How much conversation the model can see at once.
            Larger costs memory on every machine, so it comes out of what is
            available for the model itself.

        

        

          
          
          
Held back from the pool for the operating system
            and anything else this machine is doing. Two gigabytes suits a
            machine doing nothing else; raise it on one you are also using,
            because a model that takes everything will make the whole
            machine crawl. Each machine has its own figure.

        

        

          
          
          
Leave this blank. llama.cpp measures every device
            it can see, the other machines included, and fits the layers to
            what is actually there. Putting a number here switches that off
            — and if the number does not fit, llama.cpp stops rather than
            falling back, which is a confusing way to fail. Only set it if
            you have a specific reason.

        

        

          
          
          
One number per machine, this one first:
            3,2,1. Left blank, llama.cpp divides the layers by
            how much memory each machine has free, which is usually right.
            Set it by hand when memory is a poor guide — an old laptop with
            plenty of free RAM and a slow processor will take a third of the
            model and then hold everything else up.

        

        

          
          
          
Passed through untouched. Wrong options here will
            stop a model loading; the load log on the Pool page will say
            why.
